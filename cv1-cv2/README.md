## Задание 1: восстановление текста и токенизация

### 1. Понять формат CoNLL-U

Каждое предложение — блок строк. Пустая строка разделяет предложения. Строки с `#` — комментарии, например ID предложения и его текст. Остальные строки содержат десять столбцов, разделённых табуляцией, а не обычными пробелами.

| Номер | Поле | Что хранит |
| --- | --- | --- |
| 1 | ID | Номер слова, диапазон составного токена или ID пустого узла |
| 2 | FORM | Само слово или знак пунктуации |
| 3 | LEMMA | Начальная форма слова |
| 4 | UPOS | Универсальная часть речи |
| 5 | XPOS | Часть речи в разметке конкретного корпуса |
| 6 | FEATS | Грамматические признаки |
| 7 | HEAD | ID главного слова |
| 8 | DEPREL | Тип синтаксической связи |
| 9 | DEPS | Расширенные синтаксические связи |
| 10 | MISC | Дополнительные признаки, включая информацию о пробеле |

Для восстановления достаточно ID, FORM и MISC. В Python индексы начинаются с нуля, поэтому это `columns[0]`, `columns[1]`, `columns[9]`.

`SpaceAfter=No` означает, что **после данного токена нет пробела**. Например, для `Ahoj` с этим признаком и следующего токена `!` нужно получить `Ahoj!`, а не `Ahoj !`. Если признака нет, добавляем один пробел до следующего токена.

Есть два особых случая, реально встречающихся в этих файлах:

- ID вроде `10-11` обозначает один поверхностный токен, разбитый в синтаксической разметке на несколько слов. Например, `aby`. При восстановлении берём FORM строки диапазона и пропускаем её составные слова, чтобы не удвоить текст.
- ID вроде `13.1` обозначает пустой синтаксический узел. Он отсутствует в исходном тексте, поэтому его пропускаем.

Это правила [официального формата Universal Dependencies](https://universaldependencies.org/format.html). Сравниваем именно поверхностные токены, которые видны в тексте, а не внутренние синтаксические части составных токенов.

### 2. Прочитать файл

Функция `read_conllu()` открывает файл в UTF-8 и идёт по строкам:

1. На пустой строке сохраняет накопленное предложение.
2. Запоминает комментарий `# text = ...` только для последующей проверки.
3. Разделяет строки токенов через `line.split("\t")`.
4. Обрабатывает особые ID и сохраняет пары `(FORM, MISC)`.

Комментарий `# text` не подставляется вместо восстановленного текста: текст собирается из самих токенов.

### 3. Восстановить текст

Функция `reconstruct()` добавляет FORM каждого токена и проверяет `SpaceAfter=No`. Одновременно записывает начало и конец токена в символах — это понадобится для честного сравнения.

Например, для `Ahoj!` границы будут `(0, 4)` для `Ahoj` и `(4, 5)` для `!`. Конечная позиция не входит в токен, как в обычном Python-срезе `text[start:end]`.

Восстановленные предложения сохраняются в `*_reconstructed.txt`, между ними добавляется один пробел. Пробелы внутри предложений восстанавливаются по разметке. Исходные абзацы и точное расстояние между предложениями в этих файлах не заданы.

### 4. Написать собственный токенизатор

Весь принцип задаёт одно регулярное выражение:

```python
TOKEN_PATTERN = re.compile(r"\w+|[^\w\s]")
```

Его части:

- `\w+` — последовательность букв, цифр или `_`. Python поддерживает Unicode, поэтому словацкие буквы также входят в слова.
- `|` — «или».
- `[^\w\s]` — один символ, который не является символом слова или пробелом: например, запятая или кавычка.

`findall()` возвращает найденные токены. Например:

```text
Вход:   Ahoj, svet!
Выход:  ['Ahoj', ',', 'svet', '!']
```

Здесь нет готового NLP-токенизатора. Используются только стандартные `re` и `pathlib`.

### 5. Сравнить с корпусом

`finditer()` находит те же токены и сообщает их позиции. Токен считаем правильным, если его начало и конец совпадают с границами исходного поверхностного токена.

Так одинаковые слова в разных местах не смешиваются, а ошибка разбиения одного слова не сдвигает сравнение всех следующих токенов.

```text
Число совпадений = количество общих пар (начало, конец).
Разделено иначе = число исходных токенов − число совпадений.
Процент правильных = совпадения / число исходных токенов × 100.
```

Скрипт выводит количество исходных токенов, количество своих токенов, количество совпадений и процент правильных. Количество исходных токенов, разделённых иначе, можно получить как `total_gold - correct`. Отдельно проверяется восстановление текста по `# text`.

### Подробный разбор цикла в `main()`

Этот блок выполняет две отдельные проверки для каждого предложения:

1. **Токенизация:** совпадают ли границы токенов нашего регулярного выражения с границами токенов корпуса?
2. **Восстановление текста:** совпадает ли собранная строка с комментарием `# text`?

Одновременно он собирает восстановленные предложения в список для записи в файл. Все счётчики относятся к одному обрабатываемому корпусу: при следующем вызове `main()` они снова начинаются с нуля.

#### Откуда берутся предложения

```python
sentences = read_conllu(path)
```

`path` — путь к файлу корпуса. `read_conllu()` возвращает список. Каждый элемент списка — пара из двух значений: список токенов предложения и эталонная строка из комментария `# text`.

Например, для одного предложения структура будет такой:

```python
sentences = [
    (
        [("Ahoj", "SpaceAfter=No"), ("!", "_")],
        "Ahoj!",
    ),
]
```

Внутренний список содержит пары `(FORM, MISC)`. `"_"` здесь означает отсутствие дополнительных признаков. Если комментария `# text` нет, на месте `"Ahoj!"` будет `None`.

#### Зачем нужны список и счётчики

```python
texts = []
total_gold = total_predicted = correct = checked_texts = correct_texts = 0
```

`texts` — пока пустой список, куда будем добавлять восстановленные предложения.

Вторая строка присваивает **каждой из пяти переменных значение 0**. Это пять отдельных счётчиков. Изменение одного не меняет остальные. Такая запись здесь равнозначна:

```python
total_gold = 0
total_predicted = 0
correct = 0
checked_texts = 0
correct_texts = 0
```

| Переменная | Что считает | Единица |
| --- | --- | --- |
| `total_gold` | Все исходные поверхностные токены корпуса | Токены |
| `total_predicted` | Все токены, найденные нашим регулярным выражением | Токены |
| `correct` | Токены с совпавшими границами | Токены |
| `checked_texts` | Предложения, для которых есть эталонный `# text` | Предложения |
| `correct_texts` | Предложения, полностью совпавшие с эталонной строкой | Предложения |

`gold` — принятое название эталона, с которым сравнивают результат. `predicted` означает результат нашего алгоритма.

#### Как цикл получает два значения

```python
for tokens, original_text in sentences:
```

На каждом шаге Python берёт следующую пару из списка `sentences` и распаковывает её:

- `tokens` получает список пар `(FORM, MISC)` одного предложения;
- `original_text` получает строку из `# text` или `None`.

Для примера выше это:

```python
tokens = [("Ahoj", "SpaceAfter=No"), ("!", "_")]
original_text = "Ahoj!"
```

Один проход цикла обрабатывает **одно предложение**, а не один токен.

#### Что возвращает восстановление

```python
text, gold_spans = reconstruct(tokens)
```

Функция возвращает два значения, которые тоже распаковываются:

- `text` — строка, собранная из FORM и признаков пробелов;
- `gold_spans` — множество границ исходных токенов в этой строке.

`span` означает участок строки. Он записан парой `(start, end)`: начало включается, конец не включается. Индексы начинаются с нуля.

```text
Символ:  A h o j !
Индекс:  0 1 2 3 4

Ahoj → (0, 4)
!    → (4, 5)
```

Поэтому результат для нашего примера:

```python
text = "Ahoj!"
gold_spans = {(0, 4), (4, 5)}

text[0:4] == "Ahoj"
text[4:5] == "!"
```

Последние две строки показывают смысл границ; в самом блоке их нет. Это **позиции символов в текущем предложении**, а не номера токенов и не позиции байтов в файле.

`gold_spans` строится из исходных токенов корпуса. Комментарий `# text` для его построения не используется.

#### Как получаются границы наших токенов

```python
predicted_spans = {match.span() for match in TOKEN_PATTERN.finditer(text)}
```

Разберём выражение изнутри:

1. `TOKEN_PATTERN.finditer(text)` ищет в восстановленной строке все совпадения регулярного выражения. Для `"Ahoj!"` он находит `"Ahoj"` и `"!"`.
2. Каждый `match` — объект одного найденного совпадения. `match.group()` даёт найденный текст, а `match.span()` — его начало и конец.
3. Запись `{... for ... in ...}` собирает результаты в **множество**, то есть `set`. Двоеточия между ключом и значением здесь нет, поэтому это не словарь.

В более длинной, но равнозначной форме эта строка выглядела бы так:

```python
predicted_spans = set()
for match in TOKEN_PATTERN.finditer(text):
    predicted_spans.add(match.span())
```

Для `"Ahoj!"` получится:

```python
predicted_spans = {(0, 4), (4, 5)}
```

Порядок элементов множества не важен. Повторяющиеся слова не теряются: у каждого вхождения свои позиции, поэтому пары границ различаются.

#### Как считаются совпадения

```python
matches = len(gold_spans & predicted_spans)
```

`&` между двумя множествами означает **пересечение**: остаются только пары границ, которые есть в обоих множествах. `len()` считает количество этих пар.

В нашем примере:

```python
gold_spans & predicted_spans == {(0, 4), (4, 5)}
matches = 2
```

Оба токена найдены с правильными границами. Поскольку границы относятся к одной и той же строке `text`, совпадение начала и конца означает совпадение самого участка текста.

#### Как накапливается результат всего корпуса

```python
total_gold += len(gold_spans)
total_predicted += len(predicted_spans)
correct += matches
texts.append(text)
```

`a += b` здесь означает `a = a + b`.

Первые три строки добавляют результаты **текущего предложения** к общим счётчикам. `matches` на следующем шаге вычисляется заново, а `correct` сохраняет сумму совпадений всех уже обработанных предложений.

`texts.append(text)` добавляет восстановленную строку в конец списка. Позже `" ".join(texts)` соединит эти предложения пробелами для записи в файл.

После обработки единственного предложения `"Ahoj!"` значения будут такими:

```python
total_gold = 2
total_predicted = 2
correct = 2
texts = ["Ahoj!"]
```

#### Зачем отдельно сравнивать текст

```python
if original_text is not None:
    checked_texts += 1
    correct_texts += text == original_text
```

`None` означает, что эталонной строки нет. Условие проверяет, **есть ли с чем сравнить восстановленный текст**. Если строки нет, оба счётчика проверки текста остаются без изменений, но токены этого предложения всё равно учитываются выше.

Если строка есть, `checked_texts` увеличивается на 1. Далее сравниваются две строки целиком: все буквы, пробелы, пунктуация и регистр должны совпасть.

Выражение `text == original_text` возвращает `True` или `False`. При сложении Python использует `True` как `1`, а `False` как `0`. Поэтому последняя строка равнозначна более явному варианту:

```python
if text == original_text:
    correct_texts += 1
```

Для `"Ahoj!"`, совпавшего с эталоном, получаем:

```python
checked_texts = 1
correct_texts = 1
```

`correct` считает **токены**, а `correct_texts` — **целые предложения**. Эти проверки независимы: можно правильно восстановить предложение, но неправильно разбить его на токены.

#### Пример, в котором токенизатор ошибается

Предположим, что в другом корпусе число `3.14` записано одним токеном:

```python
tokens = [("3.14", "_"), ("eur", "_")]
original_text = "3.14 eur"
```

Тогда `reconstruct()` правильно восстановит строку, но наше регулярное выражение разделит число на три части:

| Источник | Токен | Границы |
| --- | --- | --- |
| Корпус | `3.14` | `(0, 4)` |
| Корпус | `eur` | `(5, 8)` |
| Наш токенизатор | `3` | `(0, 1)` |
| Наш токенизатор | `.` | `(1, 2)` |
| Наш токенизатор | `14` | `(2, 4)` |
| Наш токенизатор | `eur` | `(5, 8)` |

```python
gold_spans = {(0, 4), (5, 8)}
predicted_spans = {(0, 1), (1, 2), (2, 4), (5, 8)}
gold_spans & predicted_spans == {(5, 8)}
matches = 1
```

Если это единственное предложение, итог будет:

| Счётчик | Значение | Причина |
| --- | ---: | --- |
| `total_gold` | 2 | В корпусе два токена |
| `total_predicted` | 4 | Наш токенизатор нашёл четыре токена |
| `correct` | 1 | Только `eur` имеет правильные границы |
| `checked_texts` | 1 | Эталонный текст есть |
| `correct_texts` | 1 | Строка `3.14 eur` восстановлена правильно |

Процент правильных токенов: `correct / total_gold = 1 / 2 = 50%`. Исходных токенов, разбитых иначе: `total_gold - correct = 1`. Наших токенов без точного соответствия: `total_predicted - correct = 3`.

Хотя число разбито неверно, следующий токен `eur` всё равно засчитан правильно: мы сравниваем позиции в строке, а не элементы двух списков с одинаковыми индексами.

## Задание 2: классификация спама

### 1. Загрузить сообщения и категории

В `spam.csv` два столбца: `Message` содержит текст, `Category` — ответ. `ham` означает обычное сообщение, `spam` — спам.

Стандартный `csv.DictReader` читает строки как словари. Простой `split(",")` здесь не подходит: в сообщениях встречаются запятые и переводы строк внутри кавычек.

В файле 5572 записи, из них 415 — точные повторы сообщений. Для одинаковых сообщений конфликтующих категорий нет. Перед обучением удаляем повторы через словарь `{Message: Category}`: иначе копия тестового сообщения могла бы попасть в обучение и завысить оценку.

Остаётся 5157 сообщений: 4516 обычных и 641 спам. Кодируем ответы: `ham = 0`, `spam = 1`.

### 2. Разделить данные

`train_test_split()` выделяет 80% сообщений для обучения и 20% для проверки:

- `test_size=0.2` задаёт долю проверки;
- `random_state=42` делает разделение воспроизводимым;
- `stratify=labels` сохраняет примерно одинаковую долю спама в обеих частях.

Получается 4125 обучающих и 1032 тестовых сообщения. Модель обучаем только на первой части, метрики считаем на второй.

### 3. Построить бинарную матрицу токенов

Берём собственную функцию `tokenize()` из первого задания. Приводим сообщения к нижнему регистру, чтобы `FREE` и `free` считались одним токеном. Знаки пунктуации тоже являются токенами.

`CountVectorizer` назначает каждому уникальному токену свой столбец. Строка матрицы — сообщение. `binary=True` устанавливает значение **1**, если токен встретился хотя бы один раз, и **0**, если его нет. Число повторений не учитывается. Это [документированное поведение CountVectorizer](https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.CountVectorizer.html).

Условный пример:

| Сообщение | free | lunch | prize |
| --- | ---: | ---: | ---: |
| `free free prize` | 1 | 0 | 1 |
| `lunch` | 0 | 1 | 0 |

Практически важны две строки кода:

```python
x_train = vectorizer.fit_transform(train_messages)
x_test = vectorizer.transform(test_messages)
```

`fit_transform()` создаёт словарь токенов и матрицу обучения. `transform()` использует уже созданный словарь для теста. Словарь строим только на обучении, чтобы тестовые данные не влияли на подготовку модели; это соответствует [рекомендациям scikit-learn по предотвращению утечки данных](https://scikit-learn.org/1.7/common_pitfalls.html).

Неизвестные тестовые токены игнорируются. В результате обе матрицы имеют одинаковые 7754 столбца: обучение `(4125, 7754)`, проверка `(1032, 7754)`.

Матрица хранится в разреженном виде: большинство значений — нули. Текущая сокращённая версия скрипта выводит её размеры, а затем метрики модели.

### 4. Обучить логистическую регрессию

```python
model = LogisticRegression(max_iter=1000, random_state=42)
model.fit(x_train, y_train)
predicted = model.predict(x_test)
```

Модель учится назначать токенам веса. Токены, характерные для спама, могут повышать его вероятность, другие — понижать. Для сообщения модель складывает веса присутствующих токенов и свободный коэффициент:

```text
z = b + w1*x1 + w2*x2 + ...
p(spam) = 1 / (1 + exp(-z))
```

`fit()` подбирает веса по обучающим сообщениям и известным категориям. `predict()` выдаёт класс нового сообщения; для этой бинарной модели граница решения соответствует вероятности около 0,5. Несмотря на слово «регрессия», здесь это алгоритм классификации.

`max_iter=1000` задаёт верхнюю границу числа шагов оптимизации. Параметры модели не подбирались по тесту.

### 5. Оценить качество

Положительный класс во всех метриках — **spam**. Полученная матрица ошибок:

| Реальный класс / Предсказание | ham | spam |
| --- | ---: | ---: |
| ham | 901 | 3 |
| spam | 22 | 106 |

Значит, `TN = 901`, `FP = 3`, `FN = 22`, `TP = 106`:

- **Accuracy**: доля правильных ответов среди всех сообщений. `(TP + TN) / N = 1007 / 1032 = 97,58%`.
- **Precision**: какая доля сообщений, отмеченных моделью как спам, действительно является спамом. `TP / (TP + FP) = 106 / 109 = 97,25%`.
- **Recall**: какую долю всего настоящего спама модель обнаружила. `TP / (TP + FN) = 106 / 128 = 82,81%`.
- **F1-score**: гармоническое среднее precision и recall. `2 * precision * recall / (precision + recall) = 89,45%`.

Модель редко помечает обычные сообщения как спам, но пропускает часть спама. Поэтому высокая accuracy сама по себе не описывает всё качество: обычных сообщений заметно больше.

В текущей версии скрипта выводятся четыре метрики. Таблица ошибок выше приведена для объяснения результатов проверенного запуска.
