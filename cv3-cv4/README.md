## 1. Частотная матрица

Из CSV читаем `Message` и `Category`. Как в предыдущем упражнении, удаляем точные повторы сообщений перед разделением данных. В этом файле одинаковые сообщения не имеют конфликтующих категорий.

Остаётся 5157 уникальных сообщений из 5572 записей. Удалено 415 повторов. Это не позволяет копиям одного сообщения попасть одновременно в обучение и проверку.

Токенизация совпадает с предыдущим решением:

```python
def tokenize(text):
    return re.findall(r"\w+|[^\w\s]", text)
```

Буквы и цифры объединяются в слова, знаки пунктуации становятся отдельными токенами. `CountVectorizer` по умолчанию приводит текст к нижнему регистру, поэтому `FREE` и `free` — один токен.

```python
vectorizer = CountVectorizer(tokenizer=tokenize, token_pattern=None)
counts = vectorizer.fit_transform(messages)
```

В отличие от предыдущего задания, здесь **нет `binary=True`**. Поэтому каждая ячейка содержит число вхождений токена.

Например:

| Документ | free | prize | lunch |
| --- | ---: | ---: | ---: |
| `free free prize` | 2 | 1 | 0 |
| `lunch prize` | 0 | 1 | 1 |

Строки — документы, столбцы — уникальные токены. Это матрица «документы × термы», то есть транспонированное представление, если на лекции термы расположены по строкам. Смысл значений одинаковый.

Матрицы хранятся в разреженном формате: сохраняются ненулевые элементы, а не огромная таблица нулей.

## 2. Пять вариантов TF

Функция `compute_tf(counts, method)` преобразует частотную матрицу в TF-матрицу.

Обозначения:

- `f` — количество вхождений токена в конкретный документ;
- `sum(f)` — сумма частот всех токенов документа, то есть его длина в токенах, представленных в матрице;
- `max(f)` — частота самого частого токена в документе.

Используются формулы со скриншота:

| Название из лекции | Аргумент `--tf` | Формула для присутствующего токена |
| --- | --- | --- |
| binárna | `binary` | `1` |
| absolútna | `absolute` | `f` |
| relatívna | `relative` | `f / sum(f)` |
| logaritmická | `logarithmic` | `1 + ln(f)` |
| rozšírená | `augmented` | `0.5 + 0.5 × f / max(f)` |

Во всех вариантах **отсутствующий токен имеет вес 0**. Логарифм нуля не вычисляем. Для расширенного TF постоянную `0.5` добавляем только присутствующим токенам; иначе отсутствующие слова ошибочно получили бы вес.

На слайде основание логарифма не указано. В решении везде выбран натуральный логарифм `np.log`, то есть `ln`. Для расширенного TF используется указанное типичное значение `K = 0.5`.

Для документа `free free prize`:

| TF | free | prize |
| --- | ---: | ---: |
| binary | 1 | 1 |
| absolute | 2 | 1 |
| relative | 2/3 | 1/3 |
| logarithmic | 1 + ln(2) ≈ 1.6931 | 1 |
| augmented | 1 | 0.75 |

Смысл вариантов:

- Бинарный TF учитывает только наличие токена.
- Абсолютный сохраняет количество повторений.
- Относительный делит частоту на длину документа.
- Логарифмический уменьшает влияние многочисленных повторений.
- Расширенный сравнивает частоту с самым частым токеном документа.

### Как это записано в коде

`tf.data` содержит только сохранённые ненулевые значения разреженной матрицы. Поэтому можно заменить их единицами или применить логарифм, не затрагивая отсутствующие токены.

Для относительного и расширенного TF вычисляем отдельный знаменатель для каждой строки. Затем умножаем строку на обратное значение знаменателя. Запись `scale[:, None]` превращает список коэффициентов в столбец: у каждого документа будет свой коэффициент.

Если документ пустой или не содержит известных токенов, его знаменатель равен нулю. Через `np.divide(..., where=denominator != 0)` назначаем ему масштаб 0. Такой документ остаётся нулевым вектором.

## 3. Пять вариантов IDF

Функция `compute_idf(counts, method)` возвращает один вес на каждый столбец матрицы.

- `N` — количество документов в опорной коллекции;
- `df(t)` — количество документов, содержащих токен `t` хотя бы один раз;
- `max(df)` — максимальная документная частота среди всех токенов.

`df` отличается от общей частоты токена. Если `free` встретилось 10 раз в одном документе, этот документ добавляет к `df(free)` только **1**.

```python
df = np.asarray((counts > 0).sum(axis=0)).ravel().astype(float)
```

`counts > 0` отмечает присутствие токенов, `sum(axis=0)` суммирует документы по каждому столбцу, `ravel()` превращает результат в одномерный массив.

| Название из лекции | Аргумент `--idf` | Формула |
| --- | --- | --- |
| štandardná | `standard` | `ln(N / df)` |
| vyhladená | `smoothed` | `ln((N + 1) / (df + 1)) + 1` |
| pravdepodobnostná | `probabilistic` | `ln((N − df) / df)` |
| maximálna | `maximum` | `ln(max(df) / df)` |
| jednotková | `unit` | `1` |

У стандартного IDF редкие токены имеют больший вес. Сглаженный вариант добавляет единицы согласно формуле. Максимальный использует наибольшую документную частоту вместо `N`. Единичный оставляет только TF, без влияния IDF.

Вероятностный IDF может быть отрицательным, если токен есть более чем в половине документов. Эти конечные отрицательные значения сохраняются.

**Особый случай:** при `df = N` вероятностная формула содержит `ln(0)` и даёт минус бесконечность. Для такого токена код устанавливает вес 0, то есть исключает его вклад. Это явно выбранное правило обработки неопределённого случая, а не другая формула для остальных токенов. Такие токены присутствуют во всей опорной коллекции и не различают её документы.

Токены с `df = 0` не входят в изученный словарь. Новые неизвестные токены игнорируются при `transform()`, поэтому для них IDF не вычисляется.

## 4. Получить TF-IDF

Функция `weight()` объединяет выбранные TF и IDF:

```python
return compute_tf(counts, tf_method).multiply(idf).tocsr()
```

Это поэлементное умножение. Каждый столбец TF-матрицы умножается на IDF соответствующего токена. Здесь нет матричного произведения и суммирования разных токенов.

Например, если `TF(free) = 2`, а `IDF(free) = 3`, итоговый вес равен `6`.

Формулы реализованы вручную, поскольку стандартный `TfidfVectorizer` не предоставляет все варианты со скриншотов одной настройкой. Готовые библиотеки используются для частотной матрицы, косинусовой похожести и логистической регрессии.

## 5. Поиск по запросу

В функции `search()`:

1. Строим словарь и частотную матрицу всех уникальных сообщений.
2. Рассчитываем IDF по этой коллекции.
3. Преобразуем документы в TF-IDF с выбранным TF.
4. Через `vectorizer.transform([args.query])` получаем частоты токенов запроса в том же словаре.
5. Применяем к запросу выбранный TF и **тот же IDF**, рассчитанный по документам.
6. Вычисляем косинусовую похожесть и сортируем документы по убыванию.

Запрос не добавляется в корпус и не изменяет IDF. Неизвестные слова не создают новых столбцов. Поэтому координаты вектора запроса соответствуют координатам документов.

```python
similarities = cosine_similarity(query, documents).ravel()
order = np.argsort(-similarities, kind="stable")
```

Косинусовая похожесть:

```text
cos(q, d) = сумма(q[i] × d[i]) / (длина(q) × длина(d))
длина(q) = sqrt(сумма(q[i]²))
```

Она сравнивает направление векторов. Функция сама учитывает длины, поэтому отдельно нормализовать строки для поиска не требуется.

`argsort()` возвращает индексы документов в порядке сортировки. Минус перед похожестью даёт убывание. `stable` сохраняет исходный порядок при равных значениях.

В терминале показываются первые пять сообщений. В `search_results.csv` сохранены **все 5157 сообщений**, от самого похожего до наименее похожего. Если вектор запроса нулевой, выводится пояснение, а все похожести равны 0.

У запроса по умолчанию `free prize call now` первым найдено обычное сообщение:

```text
0.5532 [ham] Are you free now?can i call now?
```

Это допустимый результат: поиск сравнивает токены, а категория `ham/spam` не участвует в ранжировании. Короткое сообщение с совпадающими словами может оказаться ближе длинного рекламного текста. Для другого примера попробуй запрос `claim free prize reward`.

## 6. Классификация и сравнение

В функции `classify()` сначала один раз делим сообщения на 80% обучения и 20% проверки:

```python
train_test_split(messages, labels, test_size=0.2, random_state=42, stratify=labels)
```

Получаются 4125 обучающих и 1032 тестовых сообщения. `stratify` сохраняет приблизительную долю категорий, а `random_state=42` делает разделение воспроизводимым. Все 25 моделей используют одно и то же разделение.

В отличие от поисковой задачи, здесь словарь и IDF изучаются **только на обучении**:

```python
train_counts = vectorizer.fit_transform(train_messages)
test_counts = vectorizer.transform(test_messages)
idf = compute_idf(train_counts, idf_method)
```

Тестовые сообщения не должны влиять на подготовку признаков. Поэтому IDF не вычисляется по всему датасету до разделения. Это сохраняет смысл пункта задания о разделении данных и обеспечивает честную проверку.

В поиске можно использовать все документы, поскольку мы ищем в уже известной коллекции, а не оцениваем способность модели классифицировать неизвестные сообщения.

Два вложенных цикла перебирают пять TF и пять IDF. Для каждой пары:

1. Вычисляем IDF на train.
2. Преобразуем train и test с одинаковыми формулами и IDF.
3. Обучаем `LogisticRegression(max_iter=2000, random_state=42)`.
4. Получаем категории тестовых сообщений.
5. Вычисляем accuracy, precision, recall и F1.
6. Преобразуем придуманное новое сообщение с обучающим словарём и IDF и получаем его категорию.

Целевой атрибут — `Category`. Категории оставлены строками `ham` и `spam`: scikit-learn умеет обучаться непосредственно на таких метках. Для precision, recall и F1 положительный класс явно задан как `spam`.

Перед классификацией не добавляется L2-нормализация строк: модели получают именно рассчитанные веса. Это сохраняет различие масштаба между абсолютным и относительным TF. Косинусовая похожесть в поиске учитывает длины векторов самостоятельно.

### Как читать результаты

| Метрика | Значение |
| --- | --- |
| Accuracy | Доля правильных категорий среди всех тестовых сообщений |
| Precision | Доля настоящего спама среди сообщений, отмеченных как спам |
| Recall | Доля обнаруженного спама среди всего настоящего спама |
| F1 | Гармоническое среднее precision и recall |

В проверенном запуске:

| TF | IDF | Accuracy | Precision | Recall | F1 |
| --- | --- | ---: | ---: | ---: | ---: |
| logarithmic | maximum | 0.9806 | 0.9909 | 0.8516 | 0.9160 |
| binary | maximum | 0.9797 | 0.9908 | 0.8438 | 0.9114 |
| absolute | probabilistic | 0.9797 | 0.9908 | 0.8438 | 0.9114 |
| absolute | smoothed | 0.9787 | 0.9818 | 0.8438 | 0.9076 |
| binary | unit | 0.9758 | 0.9725 | 0.8281 | 0.8945 |
| relative | unit | 0.8769 | 0.6667 | 0.0156 | 0.0305 |

Полная таблица из 25 строк находится в `results/comparison.csv` и выводится в терминал. `binary + unit` воспроизводит бинарные признаки предыдущего упражнения и служит удобной точкой сравнения.

На этом разделении максимальный наблюдаемый F1 получен у `logarithmic + maximum`. Это описание эксперимента, а не гарантия лучшего результата на любых данных. Программа не подбирает и не выбирает модель автоматически по тесту: отдельно показывается та пара, которую пользователь указал аргументами.

У `relative + unit` частоты маленькие, а IDF их не увеличивает. При фиксированных настройках регуляризации логистическая регрессия почти всё относит к `ham`: recall спама очень низкий. Поэтому сравнивать только accuracy недостаточно. Параметры регуляризации здесь не подбираются, чтобы сравнить формулы при одинаковых настройках модели.

Для нового рекламного сообщения модель по умолчанию `absolute + smoothed` предсказывает `spam`. В столбце `new_prediction` файла сравнения есть ответ каждой из 25 моделей; они не обязаны совпадать.

### Где находятся предсказания тестовых сообщений

В терминале отдельно выведены первые пять предсказаний выбранной модели. Полный результат — в `test_predictions.csv`:

- `actual` — настоящая категория;
- `message` — текст тестового сообщения;
- `absolute__smoothed`, `logarithmic__maximum` и остальные 23 столбца — ответы соответствующих моделей.

Одна строка соответствует одному тестовому сообщению. Так видны все 1032 предсказания каждого варианта без вывода 25 тысяч ответов в терминал.
